# 📘 AI 入门：从概念到第一个小应用

这条路线适合刚开始学 AI、或会一点编程但不知道如何开始做 LLM 应用的人。目标不是一周内“学会 AI”，而是建立基本概念、完成一个小应用，并知道下一步该学什么。

## 先选一条学习分支

| 目标 | 建议顺序 |
| --- | --- |
| 了解 AI 能做什么，服务于工作或产品 | 体验模型 → 学会核查输出 → 研究具体业务场景 |
| 开发 AI 应用 | Python 基础 → 模型 API → 结构化输出 → [RAG 与 Agent](06-rag-agent.md) |
| 学算法或做研究 | 数学基础 → [机器学习](04-ml-path.md) → [深度学习](02-deep-learning-path.md) → 论文与复现 |
| 做数据分析 | Python / SQL → 统计与机器学习 → 数据项目 |

## 第一周学习计划

### 第 1 天：建立概念

先区分几个常用术语：

| 术语 | 简单解释 |
| --- | --- |
| AI | 让机器完成通常需要人类智能的任务这一研究与工程领域 |
| 机器学习（ML） | 从数据中学习规律，再用于预测或决策的方法 |
| 深度学习（DL） | 使用多层神经网络的机器学习方法 |
| 大语言模型（LLM） | 以语言为主要输入输出、经过大规模训练的模型类别 |
| 生成式 AI | 生成文本、图像、音频、视频或代码的 AI 系统 |

推荐观看 [3Blue1Brown 神经网络系列](https://www.3blue1brown.com/topics/neural-networks)。不需要一开始就背算法名称，先理解模型从数据中学习、再根据输入生成结果的大致过程。

### 第 2 天：体验并核查

选一个当前可用的对话模型，拿同一个真实任务试用，并记录：

- 哪些输出可以直接用，哪些需要修改？
- 哪些事实、引用或计算必须独立核查？
- 给模型补充背景、限制和输出格式后，结果有什么变化？

模型产品和免费额度变化较快，请从厂商官方产品页选择服务，不把某个模型的版本号或能力排名当作长期结论。

### 第 3–4 天：写一个最小 API 应用

先完成一个单一任务，例如把一段文字整理成固定字段的 JSON，或对一份自己的文本做问答。选择模型服务后，按其官方快速开始文档配置 SDK 和密钥。**不要把密钥写进代码仓库**；使用环境变量或服务商建议的密钥管理方式。

完成标准：能输入内容、调用模型、展示结果，并在失败时给出可理解的错误信息。先不引入 Agent 框架、向量数据库或复杂架构。

### 第 5–7 天：记录结果并选择下一步

在项目 README 写清楚安装和运行方式、一个示例输入输出、使用限制以及你如何检查结果。之后按问题选择方向：

- 回答不了私有资料问题：学 [RAG](06-rag-agent.md)。
- 需要调用搜索或其他工具：再研究工具调用与 Agent。
- 不理解模型为何产生这些结果：补 [机器学习](04-ml-path.md) 和 [深度学习](02-deep-learning-path.md) 基础。

## 关键概念速查

| 概念 | 含义 |
| --- | --- |
| Token | 模型处理文本时使用的离散单位；切分方式随模型而异 |
| 上下文窗口 | 一次请求中模型可处理的输入与输出 token 范围 |
| Embedding | 将内容映射为向量，常用于相似度检索 |
| 推理（inference） | 使用已训练模型生成预测或输出 |
| 微调（fine-tuning） | 用额外数据继续训练模型，以适配特定任务或行为 |
| RAG | 检索相关外部资料，再让模型基于资料生成回答 |
| Agent | 让模型在一定控制流程下选择并调用工具完成任务的系统 |
| 幻觉 | 模型生成了听起来合理、但缺乏事实依据或不正确的内容 |

## 学习时记住

- 模型输出需要验证，尤其是数字、来源、法律、医疗和财务信息。
- 模型能力、接口、价格和使用限制会变化；遇到具体决策时查阅官方文档。
- Prompt 技巧不能替代清晰目标、可靠数据、评测和错误处理。
- 先做一个范围小、能验证的项目，再逐步增加功能。
